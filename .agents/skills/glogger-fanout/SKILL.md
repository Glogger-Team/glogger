# Glogger Fanout

## 0. Orchestrator contract (read first)

- Parent NEVER works a slice directly: no edits, no gates, no pushes, no bot commands in any slice checkout. Parent cuts worktrees, launches workers, writes briefs, dispatches prompts AND review rounds, polls verdicts, merges clean slices, tears down.
- All slice execution (A gates, C/D loops, fix batches, pushes, PR bodies, bot posts) happens in the owning worker. B reviewers are parent-spawned (`task` scout/reviewer, non-isolated, read-only) — workers never review. A worker blocked on a parent decision (rebase, merge order, scope call) states the decision needed and stops — parent decides, worker resumes.
- One worker per slice, one slice per checkout — no second writer (see §4 Traps).

## 1. Pick slices

- Read `TODO.md` whole (note `:raw:` whole-line reads for truncated bullets).
- Prefer entries marked small with file-level scope; reject report-gated / Large / blocked items.
- Slices MUST be file-disjoint. Name each `feature/<slug>` cut from `main`.
- Confirm `main` clean (`git status --porcelain=v1 --branch`) before cutting.
- **Trivial-slice fast path.** One file, ≤30 changed lines, no behaviour change (comments, test-data fixtures with unchanged expectations, mechanical renames — never process docs: `AGENTS.md`, skills, workflows, gate scripts, which keep their B pass): single worker, A gates only, parent verifies freeze + gates and merges — no B/C/D. The slice report states explicitly `no process-behaviour change`. Write no marker; the next frozen-review pass covers the range as usual.

## 2. Cut worktrees (plain git) + launch one worker each

- Two transports. Default is **2A (`hc`, headless)** — no visible panes unless the user asked to watch. **2B (TUI)** is legacy, only when `herdr status` shows a running server (verified down on this box 2026-11-10 — 2B is dead until the user starts Herdr).
- Worktree cut is identical on both paths: `mise run worktree feature/<slug> main` from the `main` checkout via `eval` (`scripts/new_worktree.py` verifies the branch on neither side, cuts under `.herdr/worktrees/glogger/`, installs `node_modules`; an existing branch is checked out as-is, stale commits included — never reuse a slug). Confirm with `git worktree list`. Do NOT use `herdr worktree create` / `open`: both make a sidebar workspace, not a worker. Do NOT hand-cut with plain `git worktree add` either — it skips the `node_modules` install and the first push dies in `lint:typecheck`; always `mise run worktree`.

### 2A. `hc` headless workers (default)

- Prereq: `hc ls` answers (core runs standalone, no Herdr server needed — verified live 2026-11-10: `run` → `wait` → `read` → `rm` round-trips). Run `hc` via `eval`, same PATH reason as git.
- Launch one worker per slice with the brief inline: `hc run --bg --name <slice> --cwd <worktree-path> -- omp "<brief>"`. The brief is omp's first message — a `send` to a booting agent can be dropped, so never launch bare then `send` the task. Interactive only, never `omp -p`; no subagents unless the brief assigns them. Record the returned address (`tN`) — names are unique among live terminals (`[a-z0-9_-]{1,32}`). (`--kind omp` is a TUI concept; on `hc` the program IS the command — verified `agent: omp` on a plain `hc run -- omp ...` launch.)
- If the launch carried a task, check `first_message.sent` in `hc get <t>`; `false` means the task was NOT sent — `hc read` first, resolve readiness, then `send`. Never blind-resend: it may still have arrived.
- Monitor with ONE collective wait, not sequential per-slice waits: `hc wait --children any` (next news from any slice) or per-slice `hc wait <t>`. The default 180s timeout is a check-in, not failure — wait again. Child reports arrive tagged `<hc from="tN name">…</hc>` as parent input — read the actual result, never infer success from an expected outcome.
- Read/steer: `hc read --lines 100 <t>`, `hc get <t>`, `hc send <t> "<follow-up>"`. Fix batches go via `send` (same no-blind-resend rule: `read` before re-`send` after a stall/timeout).
- Visibility — when the user asked to watch, visible placement is part of launch, not a later fix: in the same turn as `run`, take space/tab IDs from `herdr-app ls`, then `hc label <t> herdr.space=<id> herdr.tab=<id>` per worker (retro-adoption is a recovery path only). Skip labels only when no space/tab exists or the user asked for background-only. Alternative: `herdr-app do tab.new --name <slice> --argv ... --task ...` (confirm exact shape via `herdr-app commands` first). Never add labels just for background workers.

### 2B. TUI visible panes (legacy — stub)

- Only when the user starts Herdr (`herdr status` serving; down on this box since 2026-11-10): split one pane per slice into the current tab, `herdr agent start <name> --kind omp --pane <id>`, dispatch every brief first (`herdr agent prompt`, no `--wait`), monitor with `herdr agent wait --until <state>`, read buffers with `pane read --format text` (bare JSON breaks on terminal graphics).

## 3. Brief shape (paste verbatim slots)

- Each brief MUST contain: existing checkout path + branch (Do NOT create another worktree) · task + TODO origin · scope file list (touch ONLY these) · explicit non-goals (sibling slices' files) · gates (`vue-tsc` / markdownlint / `cargo check` as applicable) · commit via `omp commit` (atomic-split flow; keep the `impv:`/`fix:`/`docs:` subject prefix, one small commit; if `omp` CLI is unavailable in the checkout, one conventional commit with the same prefix) · report contract (files changed, gate output, commit hash). On the `hc` path, end the brief with: `Report back with hc send <parent-terminal-address> <result or blocker> when done or stuck.` (the brief carries the parent's address explicitly — `$HC_TERMINAL_ID` inside a worker names the worker itself and self-injects, observed 2026-11-15 — never use it for the report; send explicitly to the parent address). Brief acceptance: no brief ships without that closing line with the address filled in, and after launch `hc get <t>` must show `first_message.sent` — a worker at `done` with no report is a failed handoff, not a finished slice (observed 2026-11-23: four `done`/turn-1 workers, zero reports, parent recovered via `hc read`).

## 4. Traps (learned 2026-11-08/09, fanout runs)

- **One worker per checkout — never a second writer in the same checkout.** Transport-agnostic version of the 11-08 rule: on `hc` that means no second `run` in a slice worktree; on TUI no second split pane in it. Parent removes a slice worker only after that slice is merged: `hc kill <t>; hc rm <t>` (read results first — `rm` on an unread terminal discards its scrollback), or on TUI close the worker pane (`herdr pane close <id>`) plus `pane.close`/`tab.close` for any opt-in visibility panes. Then remove the checkout with plain git (`git worktree remove --force <path>`, never `herdr worktree remove` — slice workspaces auto-vanish and it errors `workspace_not_found`), delete the branch, confirm with `git worktree list`. If removal hits transient Permission denied (something still holding the cwd handle — seen 11-09 on just-closed panes), retry once after a beat; the husk dir deletes by hand once empty.
- **Worker cwd IS the worktree — verify, don't cd.** `--cwd` on `hc run` (or split `--cwd` on TUI) sets the root; trust the shell (`git branch --show-current` in the worker), not the launch-time listing.
- **`hc wait` returning is not verdict.** `reason: timeout` is a check-in (wait again); `reason: message` arrives as parent input, not as `read` output — process it, then wait again if slices remain. Never sleep/poll around `hc`.
- **Each worktree needs its own `node_modules` — install before first gate AND first push.** `mise exec -- npm install` once per checkout (lockfile-pinned, ~10s; bare `npm` dies in the `bash` tool — use `npm.cmd`, see AGENTS.md Gotchas). Without it `vue-tsc` fails both the A gate and the pre-push `lint:typecheck`.
- **Don't trust self-reported hashes.** Workers report stale hashes; read commit IDs from branch HEAD (`git rev-parse --short HEAD`) before freezing reviews.
- **Pre-existing drift (e.g. `package-lock.json` stamp) is never yours — preserve it outside the checkout, never silently drop it.** Stash/move it before A (drift touching Rust taints `cargo test`; a dirty tree makes frozen-review read drift instead of the range) and before B-freeze; re-gate if the tree changes. At teardown it blocks `worktree remove` — same handling. Drop only with explicit authorization; say so in reports.
- **Stack is `herdr-app` + `herdr-core` — `herdr status` server-down is not a signal.** The TUI `herdr pane/agent` CLIs are dead on this stack; `herdr-app ls` is the source of truth for spaces/tabs/panes. Never gate visibility work on `herdr status`, and never report its `not running` as a blocker (observed 2026-11-23: server down, stack healthy, adoption via labels worked).

## 5. A–D per slice (values: `AGENTS.md` Code review loop)

- **A (worker executes, parent verifies):** worker runs drift handling, `mise run lint:full` + self-review checklist, re-gates after each fix batch, records freeze (`rev-parse --short HEAD`, `status --porcelain`, `log --oneline base..HEAD`, `diff --stat`) in its report. Parent verifies the freeze from `main` (branch HEAD, `git worktree list`) — never re-runs slice gates. Re-run A if the tree changes before B.
- **B (parent dispatches reviewers, read-only):** 1 reviewer per slice at this size (<100 lines or ≤2 files → 1). Parent spawns `task` reviewers itself (non-isolated, read-only `scout`/`reviewer`) — workers never review. First pass: target the full slice range from its `main` base through the frozen HEAD (`/skill:frozen-review <base>..<slice-sha>` — a bare SHA reviews only that commit and the no-marker fallback at the release tag can sweep unrelated `main` commits); if the slice froze as multiple commits (worker + stage-A fix), record a B verdict per commit at each matching frozen revision. Later batches use the `review-last` marker delta. Paste frozen hunks into briefs with "do not re-run git diff"; carry facts sheet + three intake categories + report contract. Tag the behaviour slice "may run the thing".
- **Fix batch (worker author, in its worktree):** parent forwards findings only; one batch; worker re-gates, commits, reports. Never point a reviewer at its own fix (delta-only verification pass at most once).
- While a slice has a review in flight (B, Red-team, or Closeout), queue new asks — do NOT send follow-up work into the same branch (11-09: a mid-review addition forced a second delta review; on `hc` that means no `hc send` with new scope mid-review).
- **Red-team (parent dispatches, fresh instance):** parent spawns a `task` reviewer (non-isolated, read-only `scout`/`reviewer` — workers never review) with a written break-it brief at major threshold over the frozen range: same brief shape as B (frozen hunks, facts sheet, three intake categories, report contract) plus the major bar (0 critical / 0 high / 0 fix-now mediums) and break-it posture. The brief also carries a gate-impact sweep: name every pin, self-test, chain head, or fixture the slice invalidates and show its update. Findings → one worker fix batch → A re-gate → B-delta. Never Red-team on a revision with Closeout in flight or on the same push as Closeout.
- **Closeout (worker pushes + opens PR, parent verifies, parent merges):** worker pushes branch → opens PR (title carries `impv:`/`fix:`/`docs:` prefix — squash subjects feed `next-version.py`); no bot posts, no polling. Parent dispatches the Closeout final pass (fresh reviewer, written closeout brief, `skill://simulated-d-review` chain partition on large ranges) with two jobs: verify every prior fix holds line by line, plus a fresh chain-owning sweep for new or unintended behavior in the final range; behavior fixes need executed mutant evidence (pre-fix failure output in the fix report). Fix batches return to A gates → B-delta (parent re-dispatches) → Closeout re-check. Parent merges only clean slices via the PR (merge button, never a local fast-forward + push — direct pushes to `main` are rejected, GH013).
- Parent reads PR state via `pr://<N>` (state, reviews, merge state) — never shell `gh api` + hand-parse JSON in eval (11-09: quoting bugs, truncated bodies, 3+ re-fetches).
- **Close:** 0 critical / 0 high / 0 fix-now mediums in changed code. Any commit past the B freeze — even a 4-line Closeout fix — needs its own delta A/B before merge; no new A–B = the loop silently skips two steps. Marker `review-last` is local, never pushed.
